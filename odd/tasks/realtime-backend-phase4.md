# Phase 4 specs (companion of odd/tasks/realtime-backend.md)

Verified facts (official pages, checked 2026-11-07). Leads are COMPANIES; never store personal data.

## Source facts
- **RemoteOK** `GET https://remoteok.com/api`: JSON array, element 0 is a legal notice object `{last_updated, legal}`, jobs from element 1: `slug,id,epoch,date,company,company_logo,position,tags,description,location,salary_min,salary_max,url,apply_url`. Legal text: "Please link back (with follow, and without nofollow!) to the URL on Remote OK and mention Remote OK as a source". robots.txt `Crawl-delay: 1`, `Disallow: /@` for AI crawlers (never touch profile pages). No documented rate limit, no auth. The feed has NO company domain: derive the domain from `apply_url`/`url` host only when it is a company host (exclude remoteok.com and known ATS/aggregator hosts: greenhouse.io, lever.co, ashbyhq.com, workable.com, smartrecruiters.com, myworkdayjobs.com, bamboohr.com, recruitee.com, jobs.* aggregators, linkedin.com, indeed.com, etc.); otherwise SKIP the job and count it as `skippedNoDomain`. Store title, location, tags (max 10), salary range, job url; NOT description, NOT logo. Every stored signal payload carries `attribution: { name: 'Remote OK', url: <job url on remoteok.com> }` and the desktop lead detail panel must show a "via Remote OK" link when a signal has it.
- **GitHub REST** `https://api.github.com`: token from env GITHUB_TOKEN (Bearer), header `Accept: application/vnd.github+json`, a valid `User-Agent` is REQUIRED (use SCRAPER_USER_AGENT). Primary limit 5,000/hour authenticated; response headers `x-ratelimit-limit|remaining|used|reset(epoch s)|resource`; when primary limit is exceeded wait until `x-ratelimit-reset`; secondary limit gives 403/429 with optional `retry-after` (seconds), otherwise wait >= 60 s. Endpoints: `GET /orgs/{org}/repos?type=public&sort=created&direction=desc&per_page=30` and `GET /repos/{owner}/{repo}/releases?per_page=5`. Keep only repo `name, full_name, created_at, pushed_at, language, topics, stargazers_count, html_url` and release `tag_name, name, published_at, prerelease, html_url`. NEVER store owner/author logins, emails, contributors. ToS forbids selling personal data to recruiters: we only keep org-level metadata. One task = one org = at most 4 HTTP requests (1 repos list + releases of the 3 most recently pushed repos), spaced >= 250 ms. Signals (type `oss-activity`): `new-repo` for repos created in the last 90 days (externalId `gh:{org}:repo:{full_name}`), `release` for releases published in the last 90 days (externalId `gh:{org}:release:{full_name}:{tag}`). Config field `githubOrg` per company entry.
- **SEC EDGAR**: max 10 requests/second across all machines (we limit to 4/s); every request MUST send header `User-Agent` = env SEC_EDGAR_USER_AGENT (descriptive, includes contact info, e.g. `Company Name admin@example.com`) and `Accept-Encoding: gzip, deflate`; exceeding the limit can block the IP for a while, so on 403/429 back off hard (>= 10 minutes pause of the queue). Endpoints: `GET https://www.sec.gov/files/company_tickers.json` (map of index -> {cik_str, ticker, title}; fetch ONCE per process and cache 24 h) and `GET https://data.sec.gov/submissions/CIK{cik padded to 10 digits}.json` where `filings.recent` holds parallel arrays `form, filingDate, accessionNumber, primaryDocument`. Only issuer-level forms: 8-K, 10-K, 10-K/A, 10-Q, S-1, S-1/A, 424B4, 6-K, 20-F; NEVER insider forms (3, 4, 5, SC 13D/G, etc.). Only filings of the last 90 days. Signal type `filing`, externalId `sec:{cik}:{accessionNumber}`, payload `{form, filingDate, url: https://www.sec.gov/Archives/edgar/data/{cik}/{accession without dashes}/{primaryDocument}}`. Config field `secTicker` resolves the CIK; SAFETY: skip (record an error for that target) when the EDGAR `title` does not loosely match the configured company name (normalized, first significant token), because the tickers in the config were not verified.
- **Website enrichment** (RFC 9309): fetch `https://{domain}/robots.txt` first. Matching group by case-insensitive product token (ours: `LeadsSalesIntelligenceBot`), else `*`, else no rules; multiple matching groups are merged; longest matching path wins, Allow wins ties; 4xx on robots.txt = no restrictions; 5xx or network error or > 5 redirects handled per RFC (5xx/network => assume FULL DISALLOW; many redirects => unavailable); cache robots per host <= 24 h; honor a published `Crawl-delay` (not part of the RFC) as the minimum spacing. If `/` is disallowed -> skip the company (record `robotsDisallowed`). One page per company: the home page `/`. Extract: `<title>`, meta description / og:description, `<meta name="generator">`, response headers `server`, `x-powered-by`, plus tech hints from HTML (script/link URLs and markers: WordPress `/wp-content/`, Shopify `cdn.shopify.com`, Next.js `__NEXT_DATA__`/`/_next/`, Nuxt, React/Vue markers, Webflow, Squarespace, HubSpot `js.hs-scripts.com`, Segment `cdn.segment.com`, Google Analytics/GTM, Intercom, Cloudflare via `server: cloudflare`...) as a pure function `detectTech(html, headers)`. Send User-Agent `LeadsSalesIntelligenceBot/0.1 (+https://github.com/rllapur89/sales-intelligence-scraping)`. Targets for the `website` source come from the Company table (domains of existing companies), not from the config file. Output: one item per company with `signal.type = 'website-tech'`, externalId `web:{domain}:{yyyy-mm}` (one per month), `company.description` and `company.techHints` filled. Fetcher interface `PageFetcher` with `HttpPageFetcher` (default, plain fetch with timeout and max body 1 MB) and `PlaywrightPageFetcher` (selected by env WEBSITE_FETCHER=playwright; uses `playwright-core` loaded with a dynamic import so it is optional; Chromium is installed by the user with `npx playwright install chromium`, DO NOT run that install); concurrency 1.
- **Hacker News**: NOT implemented (terms unclear, waiting for the owner). Leave `hn-hiring` unreviewed.

## Specs
- S50: Scrapers `remoteok`, `github`, `sec-edgar`, `website` in `apps/workers/src/scrapers/`, each a class implementing `Scraper`, each with RECORDED fixtures under `apps/workers/test/fixtures/` (build small fixtures from the real response shapes; one live request per source is allowed ONLY to record a fixture: RemoteOK and GitHub unauthenticated (60/h, keep it tiny) are OK; do NOT call SEC EDGAR with any invented contact: skip a live SEC fixture and hand-write one from the documented shape) and unit tests with NO live network.
- S51: `http-client.ts`: extend `createJsonFetcher` with optional extra `headers` and a rate-limit-aware retry-after: on 403/429 with `x-ratelimit-remaining: 0` derive `retryAfterMs` from `x-ratelimit-reset`; keep it backwards compatible (existing tests stay green; add tests).
- S52: Wiring in `queues/queue.service.ts`: register the new scrapers; start a source only when `policy.reviewed` AND every `policy.requiredEnv` variable is set (log which source was skipped and why); `loadTargets` per source (github: companies with githubOrg; sec-edgar: companies with secTicker; remoteok: one synthetic feed target `{slug:'feed', name:'Remote OK', domain:'remoteok.com'}`; website: Company rows from Postgres, optional slug filter by domain); a single-request source such as remoteok yields many companies from one task. SEC: share one cached ticker->CIK map. Add env vars to `.env.example` (WEBSITE_FETCHER) and to `apps/workers/src/config/env.ts` where needed.
- S53: Ingestion: `RawSignalItem.company.description` / `techHints` are persisted by `IngestionService` as enrichment: fill-gaps for description, UNION for techHints (max 30), never erase; the lead is re-emitted (new seq) when enrichment changed something visible. Update `toLeadDto` usage/tests. Keep idempotency: re-ingesting identical data emits nothing.
- S54: Scoring v2 in `ingestion/score.ts` (pure, tested): per-signal-type weight instead of counting all signals equally. Suggested: hiring volume log term as today; `filing` 25 points for a filing within 30 days (10 if within 90) capped, `oss-activity` up to 15 (new repo 8, release 5, with recency), `website-tech` 5 once, diversity bonus per extra live type stays. Final 0-100. Document the formula in the file header and in README.
- S55: `docs/sources.md`: add a section per implemented source (RemoteOK, GitHub, SEC EDGAR, website enrichment) in the same table format as the existing ones, quoting the facts above (limits, attribution, UA rules, what we store, what we avoid), plus a "Hacker News (not implemented)" section explaining why (YC terms ban scraping the site and bots; Algolia HN API terms for this use not clear; needs the owner's decision). Update the limiter/our-limit rows to match `SOURCE_POLICIES`.
- S56: RemoteOK attribution in the desktop lead detail panel: when a signal payload has `attribution`, render "via {name}" as a link (`target=_blank rel="noopener"`); the REST lead detail already returns signals; if the client currently doesn't show signals add a compact "Recent signals" list (type, title/label, date, source link) to the detail panel. Keep within apps/desktop/src/**; unit-test the pure formatting helper.
