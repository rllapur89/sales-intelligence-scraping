## Phase 3 backend specs (delegated unit: apps/api auth + subscriptions + gateway)
- S30: Auth: `POST /api/auth/login {email,password}` -> {accessToken, refreshToken, user:{id,email,displayName,role}}; `POST /api/auth/refresh {refreshToken}` rotates both tokens (old refresh invalid); `GET /api/auth/me`. @nestjs/jwt, secrets JWT_ACCESS_SECRET/JWT_REFRESH_SECRET, TTL JWT_ACCESS_TTL/JWT_REFRESH_TTL (.env.example already documents them), bcryptjs compare against User.passwordHash, store only a hash of the current refresh token (User.refreshTokenHash). Wrong credentials -> 401 with the same message for unknown email and wrong password.
- S31: A global JwtAuthGuard protects every REST route except health, login, refresh and /docs; `@Public()` decorator. Remove the "no auth yet (phase 3)" comments. Update swagger bearer auth.
- S32: Subscriptions CRUD scoped to the authenticated user: `GET/POST /api/subscriptions`, `PATCH/DELETE /api/subscriptions/:id` (404 for another user's id). Body: name, active, industries[], regions[], signalTypes[] (SignalType), minScore 0-100; DTOs use `SubscriptionFilter`/`SubscriptionDto` from @leads/shared. A user with NO active subscription receives nothing live; seed (packages/db/prisma/seed.ts) must create an active "All leads" subscription (empty arrays, minScore 0) for each demo user, idempotently.
- S33: Socket.IO gateway (@nestjs/websockets + platform-socket.io, `@socket.io/redis-adapter` so several API instances work). Handshake authenticated with the SAME access JWT in `auth.token`; invalid/expired -> connection rejected with an error the client can detect ('unauthorized'). CORS from CORS_ORIGIN. Contract = ServerToClientEvents/ClientToServerEvents in packages/shared/src/events.ts (extend there if needed, keep it backwards compatible).
- S34: Each API instance subscribes to Redis channel LEAD_EVENTS_CHANNEL (plain pub/sub; every instance sees every event) and buffers events for GATEWAY_BATCH_WINDOW_MS (default 200, env-configurable). On flush it COALESCES per lead id (highest seq wins), then for each connected socket sends one `leads:batch` {fromSeq,toSeq,leads,timings} containing only leads matching ANY of that user's active subscriptions (industry, region, any-overlap signalType, minScore; empty array = any). Sets `timings[leadId].publishedAt = Date.now()` right before emit. Pure functions `matchesFilter` and the coalescer must be unit-tested; subscription changes (CRUD) refresh the live sockets of that user (also across instances via a Redis pub/sub message).
- S35: Backpressure: per socket keep a pending Map<leadId, lead+timings>; if the socket's outbound buffer is not drained (engine `writeBuffer.length` above a threshold, configurable), merge newer versions of the same lead into the map instead of queueing another batch, and send on the next tick when drained. Unit-test this buffer as a class with an injected "isDrained" function.
- S36: Resync: client emits `leads:resync {lastSeq}` with an ack callback. Server: `lastSeq <= 0` or `lastSeq > currentSeq` -> {mode:'full', reason:'unknown-seq', currentSeq}; `currentSeq - lastSeq > GATEWAY_REPLAY_MAX_GAP` (default 5000) -> {mode:'full', reason:'gap-too-large'}; else replay from the LeadEvent table (seq > lastSeq - 100 overlap, because autoincrement ids can become visible out of commit order; clients ignore versions older than what they hold), coalesced per lead (latest payload), filtered by the user's subscriptions, chunked into batches of <=500 leads -> {mode:'delta', batches, currentSeq}. `planResync(lastSeq, currentSeq, maxGap)` is a pure function with unit tests. Also emit `leads:resync-required` to a client that connects and is already behind? No: the client drives it.
- S37: `latency:ack` handler: validate (array, max 100 items, numeric fields, ignore malformed), hand to an `AckSink` provider (phase 5 will turn it into Prometheus histograms; for now an in-memory counter + debug log).
- S38: Tests: unit tests for matchesFilter, coalescer/batcher (fake timers), per-socket backpressure buffer, planResync, JWT handshake verification, auth service (mock prisma), subscriptions service (mock prisma). PLUS one integration spec `apps/api/src/integration/gateway.integration.spec.ts`, skipped unless INTEGRATION_TESTS=1, against real Postgres+Redis (docker compose is running; dedicated schema `integration`): login as the seeded demo user, connect with socket.io-client, publish a LeadUpsertedEvent on Redis, assert the batch arrives within ~1s with publishedAt set, assert a non-matching subscription receives nothing, assert resync delta/full. IMPORTANT host constraint: this Windows host is memory-starved; run node/vitest with `NODE_OPTIONS=--max-semi-space-size=1`, run ONE process at a time, never start the api and workers and vitest simultaneously, and do not start Docker services (postgres+redis are already up).
